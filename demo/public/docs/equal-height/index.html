FullWidthEqualHeightMasonry

Google Photos style layout: images keep their aspect ratio, every row has one height and is stretched or shrunk to fill the container width exactly.

Usage

import { FullWidthEqualHeightMasonry } from "react-hybrid-masonry";

<FullWidthEqualHeightMasonry
  loadData={loadData}
  pageSize={30}
  targetRowHeight={245}
  sizeRange={[230, 260]}
  maxItemWidth={975}
  gap={8}
  renderItem={(item) => (
    <div
      style={{
        position: "absolute",
        left: item.x,
        top: item.y,
        width: item.width,
        height: item.height,
      }}
    >
      <img src={item.url} alt={item.title} style={{ width: "100%", height: "100%", objectFit: "cover" }} />
    </div>
  )}
/>

Props

PropTypeDefaultDescription

renderItem(item, index) => ReactNoderequiredRenders one positioned item. index is the position in all loaded data.

targetRowHeightnumber245Preferred row height. The real height is adjusted within sizeRange.

gapnumber8Gap between items, horizontally and vertically, in px.
buffernumber1500Extra distance in px that is still rendered around the viewport.
loadMoreThresholdnumber500Distance in px from the bottom at which the next page is requested.
mapSize(raw) => { width, height }–Maps your data to dimensions.
enableAnimationbooleantrueReserved. It has no effect yet.

How it behaves

  • Rows are built greedily: images are added to a row while filling the row would need an enlargement above maxStretchRatio. Rows may shrink images as much as needed.
  • The row height is then clamped to sizeRange, and widths are distributed so that the row ends exactly at the container edge, without leaving rounding errors on the last image.
  • The last row is not stretched. It keeps natural proportions (at most targetRowHeight high), so a few images are never blown up. When the next page arrives, that row is recomputed.
  • No item is wider than maxItemWidth, so a very wide panorama does not take the whole row.

The full procedure is described in how the equal-height algorithm works.

Tuning

GoalChange
Larger photos, fewer per rowRaise targetRowHeight and sizeRange, for example 320 and [300, 360].
Tighter justificationNarrow sizeRange; rows then fill the width by choosing different image counts rather than by scaling.
Avoid heavily enlarged rowsLower maxStretchRatio towards 1.2; more images are put into a row before it is closed.
Prevent giant panoramasLower maxItemWidth.
