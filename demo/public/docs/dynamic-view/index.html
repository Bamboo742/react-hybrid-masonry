DynamicMasonryView

One component, two layouts. The layout is controlled by a prop, by the first API response, or by a default.

Three ways to pick the layout

1. Controlled

TSX
<DynamicMasonryView
  isMasonry={useWaterfall} // true = waterfall, false = equal-height
  loadData={loadData}
  renderItem={(item, index, isMasonry) => /* ... */ null}
/>

The prop has priority over everything else. When it changes the active layout is remounted and loads from page 1 again.

2. From the first API response

TSX
<DynamicMasonryView
  loadData={async (page, pageSize) => {
    const res = await fetch("/api/content?page=" + page + "&size=" + pageSize);
    const json = await res.json();
    return page === 1
      ? { data: json.items, hasMore: json.hasMore, isMasonry: json.layoutType === "waterfall" }
      : { data: json.items, hasMore: json.hasMore };
  }}
  renderItem={(item, index, isMasonry) => /* ... */ null}
/>

The component calls loadData(1, pageSize) once on mount, reads isMasonry from the result and caches that first page, so the chosen layout shows it right away and page 1 is not requested a second time. The layout type is read only once; later pages do not need to return it.

3. Default value

If loadData does not return isMasonry, defaultIsMasonry (default true) is used. If the first request fails, onError is called and the default layout is used.

Exported types

TSX
import {
  DynamicMasonryView,
  ViewType, // enum: ViewType.Waterfall = 1, ViewType.EqualHeight = 2
} from "react-hybrid-masonry";
import type { DynamicMasonryViewProps, LoadDataFn } from "react-hybrid-masonry";
loadData is declared as LoadDataFn<T>; only the first call may include isMasonry. Related: pagination and infinite scroll.
