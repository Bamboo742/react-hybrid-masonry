VirtualMasonry

Pinterest style waterfall layout: equal-width columns, items keep their aspect ratio and are placed into the shortest column. Only items near the viewport are rendered.

Usage

TSX
import { VirtualMasonry } from "react-hybrid-masonry";

<VirtualMasonry
  loadData={loadData}
  pageSize={30}
  minColumnWidth={200}
  maxColumnWidth={350}
  gap={16}
  renderItem={(item) => (
    <div
      style={{
        position: "absolute",
        left: item.x,
        top: item.y,
        width: item.width,
        height: item.height,
      }}
    >
      <img src={item.url} alt={item.title} style={{ width: "100%", height: "100%", objectFit: "cover" }} />
    </div>
  )}
/>

Props

PropTypeDefaultDescription
loadData(page, pageSize) => Promise<{ data: any[]; hasMore: boolean }>–Loads one page. Page numbers start at 1. Without it the component stays empty.
renderItem(item, index) => ReactNoderequiredRenders one item. index is the position among the currently rendered items.
pageSizenumber50Items requested per page.
minColumnWidthnumber200Minimum column width in px. The calculated column count never makes columns narrower than this.
maxColumnWidthnumber–Maximum column width in px.
columnsnumber–Fixed column count. Skips the width based calculation.
gapnumber16Gap between items, horizontally and vertically, in px.
buffernumber1500Extra distance in px above and below the viewport that is still rendered.
loadMoreThresholdnumber800Distance in px from the bottom at which the next page is requested.
mapSize(raw) => { width, height }–Maps your data to dimensions. See the data contract.
initialItemsany[]–A first page you already have (for example from SSR). Page 1 is not requested again; loading continues at page 2.
initialHasMorebooleantrueUsed with initialItems: whether more data exists after the first page.
enableAnimationbooleantrueReserved. It has no effect yet.

How the column count is chosen

  1. If columns is set, it is used as is.
  2. Otherwise floor(containerWidth / minColumnWidth) columns are used, at least 1.
  3. If maxColumnWidth is set and the columns would be wider than that, columns are added one by one (up to 20) until they fit, but a column is not added when it would make columns narrower than minColumnWidth. When both limits cannot be met, the minimum wins.

The column width is (containerWidth - gap * (columns - 1)) / columns, capped at maxColumnWidth. When the cap applies, the grid is left aligned and the remaining space stays empty on the right.

An item's height is columnWidth * (height / width) of its original size, and it is placed into the column that is currently the shortest.

Examples

Fixed number of columns

TSX
<VirtualMasonry columns={4} gap={12} loadData={loadData} renderItem={renderCard} />

Pick the number per breakpoint with a small hook, see responsive layouts.

Start from data you already have

TSX
<VirtualMasonry
  initialItems={firstPage.items}
  initialHasMore={firstPage.hasMore}
  loadData={loadData} // first call will be page 2
  renderItem={renderCard}
/>

Item sizes in other fields

TSX
<VirtualMasonry
  mapSize={(raw) => ({ width: raw.imgW, height: raw.imgH })}
  loadData={loadData}
  renderItem={renderCard}
/>
