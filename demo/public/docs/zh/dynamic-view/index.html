DynamicMasonryView

一个组件，两种布局。布局由属性、第一次接口返回或默认值决定。

概览

DynamicMasonryView 是 VirtualMasonry（瀑布流）和 FullWidthEqualHeightMasonry（等高布局）外面的一层选择器：由接口告诉它这个列表该用哪种展示形式，所以运营或后端可以按内容（图片为主还是带文字的卡片）切换，前端不用写两份页面。

  • 组件只负责选择，真正的排版、虚拟滚动和翻页都由内部的两个组件完成，行为和它们单独使用时一致。
  • 两种布局共用同一个 loadData、renderItem 和 mapSize，你只需要写一份数据层和一份卡片。
  • 非受控模式下，第 1 页只请求一次：用来读取布局类型的那次请求，结果会直接交给内部组件使用。

快速上手

最常见的用法：接口在第一页里告诉组件用哪种布局。

TSX
import { DynamicMasonryView } from "react-hybrid-masonry";

async function loadData(page: number, pageSize: number) {
  const res = await fetch("/api/content?page=" + page + "&size=" + pageSize);
  const json = await res.json();
  return page === 1
    ? { data: json.items, hasMore: json.hasMore, isMasonry: json.layoutType === "waterfall" }
    : { data: json.items, hasMore: json.hasMore };
}

export function Feed() {
  return (
    <DynamicMasonryView
      loadData={loadData}
      pageSize={30}
      waterfallConfig={{ minColumnWidth: 200, maxColumnWidth: 350, gap: 16 }}
      equalHeightConfig={{ targetRowHeight: 245, sizeRange: [230, 260], gap: 8 }}
      renderItem={(item, index, isMasonry) => (
        <div
          key={item.id}
          style={{
            position: "absolute",
            left: item.x,
            top: item.y,
            width: item.width,
            height: item.height,
            borderRadius: isMasonry ? 12 : 6,
            overflow: "hidden",
          }}
        >
          <img src={item.url} alt={item.title} style={{ width: "100%", height: "100%", objectFit: "cover", display: "block" }} />
        </div>
      )}
    />
  );
}
每条数据在加载之前就必须带有宽和高，两种布局都靠它们算位置，约定和VirtualMasonry、FullWidthEqualHeightMasonry一致。

三种确定布局的方式

1. 受控

TSX
<DynamicMasonryView
  isMasonry={useWaterfall} // true = 瀑布流，false = 等高布局
  loadData={loadData}
  renderItem={(item, index, isMasonry) => /* ... */ null}
/>

该属性优先级最高。传了它，组件不会为了确定布局而提前请求第 1 页，loadData 返回里的 isMasonry 也会被忽略。它变化时，当前的布局组件会被卸载、另一个被挂载，并从第 1 页重新加载。

2. 由第一次接口返回决定

没有传 isMasonry 时，组件挂载后调用一次 loadData(1, pageSize)，从结果里读取 isMasonry，并缓存这第一页数据，所以选好的布局会立刻展示它，第 1 页不会被请求第二次。布局类型只读取一次，后续页不需要再返回。

3. 默认值

如果 loadData 没有返回 isMasonry，则使用 defaultIsMasonry（默认 true，即瀑布流）。loadData 没有传时也使用它。

如果第一次请求失败，会调用 onError 并使用默认布局。此时没有缓存的第 1 页，内部组件会再请求一次第 1 页；如果这次仍然失败，内部组件会停止翻页，不会无限重试。

受控切换示例

让用户自己选择展示形式时，把状态放在你自己这里：

TSX
function Gallery() {
  const [isMasonry, setIsMasonry] = useState(true);

  return (
    <>
      <div role="group" aria-label="布局">
        <button aria-pressed={isMasonry} onClick={() => setIsMasonry(true)}>瀑布流</button>
        <button aria-pressed={!isMasonry} onClick={() => setIsMasonry(false)}>等高布局</button>
      </div>

      <DynamicMasonryView isMasonry={isMasonry} loadData={loadData} renderItem={renderCard} />
    </>
  );
}
  • 切换会重新挂载布局组件，列表从第 1 页重新加载，滚动位置不会保留，见常见问题。
  • 挂载时和每次 isMasonry 变化都会调用 onLayoutTypeLoaded。
  • 受控模式下没有「等待布局类型」的阶段，所以不会显示 renderInitialLoader。

renderItem 与卡片

renderItem(item, index, isMasonry) 比单个组件多一个参数，告诉你这一次渲染用的是哪种布局，可以让同一张卡片适配两种形态。item 的字段（x、y、width、height 等）与对应的单个组件相同，根元素同样必须是绝对定位。

瀑布流（isMasonry 为 true）等高布局（isMasonry 为 false）
index当前已渲染元素中的序号，滚动时会变全部已加载数据中的序号，滚动时不变
item.width列宽，同一次布局里相同每张图各不相同
item.height按比例算出，各不相同同一行内相同
卡片内容高度可以不同，适合带文字说明只适合图片为主，文字叠在图片上

无论哪种布局，都请用 key={item.id} 这样稳定的值，不要用 index 做 key。

两种布局的配置

waterfallConfig 传给瀑布流，equalHeightConfig 传给等高布局。不传的字段使用对应组件的默认值，两个对象不会互相影响，所以可以同时写好，由接口决定用哪一个。

waterfallConfig

字段类型默认值说明
minColumnWidthnumber200最小列宽（px），用来推算列数。
maxColumnWidthnumber–最大列宽（px）。
columnsnumber–直接指定列数，不再按宽度推算。
gapnumber16元素之间的间距（px）。
buffernumber1500视口上下仍会渲染的缓冲距离（px）。

列数的计算规则见 VirtualMasonry 的列数与列宽。

equalHeightConfig

字段类型默认值说明
targetRowHeightnumber245目标行高，决定一行放几张。
sizeRange[number, number][230, 260]允许的行高范围。
maxItemWidthnumber975单个元素的最大宽度。
maxStretchRationumber1.5一行最多愿意把图片放大多少。
gapnumber8元素之间的间距（px）。
buffernumber1500视口周围仍会渲染的缓冲距离（px）。

每个字段怎么协同见 FullWidthEqualHeightMasonry 的参数说明。把 sizeRange 提到组件外面或用 useMemo，避免每次渲染都传新数组导致全部行重新计算。

这里只开放了上面这些字段。loadMoreThreshold、initialItems、initialHasMore 没有通过 DynamicMasonryView 暴露，内部使用各自组件的默认值（瀑布流 800、等高布局 500）。需要时请直接使用对应的单个组件。

属性

属性类型默认值说明
isMasonryboolean–受控模式。true 为瀑布流，false 为等高布局。
defaultIsMasonrybooleantrueloadData 没有返回 isMasonry（或没有传 loadData）时使用。
loadDataLoadDataFn–(page, pageSize) => Promise<{ data, hasMore, isMasonry? }>。

waterfallConfig{ minColumnWidth, maxColumnWidth, columns, gap, buffer }{}传给 VirtualMasonry。
equalHeightConfig{ targetRowHeight, sizeRange, maxItemWidth, maxStretchRatio, gap, buffer }{}传给 FullWidthEqualHeightMasonry。
pageSizenumber50每页请求的数据量。

加载状态与错误

确定布局之前

非受控模式要等第 1 页返回才知道用哪种布局。这段时间渲染的是 renderInitialLoader() 的返回值；不传就是一块空白。骨架屏的写法：

TSX
<DynamicMasonryView
  loadData={loadData}
  renderInitialLoader={() => (
    <div style={{ display: "grid", gridTemplateColumns: "repeat(auto-fill, minmax(200px, 1fr))", gap: 16 }}>
      {Array.from({ length: 8 }, (_, i) => (
        <div key={i} style={{ height: 160 + (i % 3) * 40, borderRadius: 12, background: "rgba(128,128,128,0.15)" }} />
      ))}
    </div>
  )}
  renderItem={renderCard}
/>

onLayoutTypeLoaded 与 onError

  • onLayoutTypeLoaded(isMasonry)：布局类型确定后调用，无论它来自属性、接口返回还是默认值。可以用来同步你自己界面上的切换按钮。
  • onError(error)：只在用来确定布局的第一次请求失败时调用，随后使用默认布局。
  • 后续页面的请求失败由内部组件处理：在控制台输出错误并停止自动翻页，不会调用你的 onError。需要感知这类失败时，请在你自己的 loadData 里 try/catch。

服务端渲染

这个组件只能在客户端工作，列表本身要等浏览器里测量到容器宽度才会排出来。非受控模式还要再等第 1 页返回，所以服务端渲染的 HTML 里没有卡片。要避免挂载后的空白，可以在服务端先决定好布局，再通过 isMasonry 传入，省去等待布局类型的那一步。需要让搜索引擎收录内容时，请另外渲染一份可抓取的列表，见 Next.js 与 SSR。

导出的类型

TSX
import { DynamicMasonryView, ViewType } from "react-hybrid-masonry";
import type { DynamicMasonryViewProps, LoadDataFn } from "react-hybrid-masonry";

// ViewType 是一个枚举：ViewType.WATERFALL = 1，ViewType.EQUAL_HEIGHT = 2
// 组件本身不读取它，它只是方便你把接口里的数字映射成 isMasonry：
const isMasonry = json.viewType === ViewType.WATERFALL;
loadData 的类型是 LoadDataFn<T>，只有第一次调用（page === 1）可以带上 isMasonry。

常见问题

接口返回的布局类型变了，为什么布局没有切换？

非受控模式下，布局类型只在第一次 loadData(1) 时读取一次，之后的页不再看它。要在运行时切换，请使用 isMasonry 属性。

切换布局后为什么从头开始加载？滚动位置也没了？

瀑布流和等高布局是两个不同的组件，isMasonry 变化时当前的那个会被卸载、另一个被挂载，新的组件从第 1 页开始加载，列表从头重新长出来，之前的滚动位置不会保留。这是预期行为：两种布局的位置计算完全不同，没办法在它们之间复用已排好的结果。如果希望保留浏览位置，请不要在用户滚动到深处时切换布局。

第 1 页会被请求两次吗？

正常情况下不会。非受控模式下组件挂载时请求一次 loadData(1, pageSize)，结果会被缓存，内部的布局组件直接取用这份缓存。只有第一次请求失败时才会例外：这时没有缓存，内部组件会再请求一次第 1 页。

受控模式下，loadData 返回的 isMasonry 为什么被忽略？

isMasonry 属性的优先级最高。传了它，组件不会为了确定布局而提前请求第 1 页，loadData 返回里的 isMasonry 也不会再被读取，只有 isMasonry 属性本身决定布局。

页面刚打开时有一段空白，怎么处理？

非受控模式要先等第 1 页返回才知道用哪种布局，这段时间显示的是 renderInitialLoader（不传就是一块空白）。传一个骨架屏给它；或者在服务端就决定好布局，通过 isMasonry 属性传进来，这样就没有这段等待。

能同时使用 initialItems 吗？

DynamicMasonryView 目前没有 initialItems 和 initialHasMore。需要用预取的首屏数据时，请直接使用 VirtualMasonry（它支持 initialItems），自己决定用哪种布局。

两种布局想共用一张卡片组件怎么办？

renderItem 的第三个参数告诉你当前用的是哪种布局，在同一个卡片组件里按它调整圆角、文字大小等即可。注意两种布局里 index 的含义不同，不要用它当 key，请使用 item.id。
