Next.js 与服务端渲染

哪些能在服务端运行，哪些要等到浏览器里，以及如何交接预取好的第一页。

加上 use client 指令

这些组件使用了 React hooks，发布时没有带指令。在 Next.js App Router 中，请在客户端文件里引入它们：

"use client";

import { VirtualMasonry } from "react-hybrid-masonry";

export default function Gallery({ first }: { first: { items: any[]; hasMore: boolean } }) {
  return (
    <VirtualMasonry
      initialItems={first.items}
      initialHasMore={first.hasMore}
      loadData={(page, size) => fetch("/api/images?page=" + page + "&size=" + size).then((r) => r.json())}
      renderItem={(item) => <Card item={item} />}
    />
  );
}

传入预取的第一页

在服务端组件里取好第 1 页，作为 initialItems 传入。组件会直接用这份数据开始，不会显示加载状态，也不会再请求第 1 页；第一次 loadData 调用请求的是第 2 页。

// app/gallery/page.tsx（服务端组件）
import Gallery from "./Gallery";

export default async function Page() {
  const res = await fetch("https://api.example.com/images?page=1&size=30");
  const first = await res.json();
  return <Gallery first={{ items: first.items, hasMore: first.hasMore }} />;
}
initialItems 只在 VirtualMasonry 上提供。DynamicMasonryView 和 FullWidthEqualHeightMasonry 的第一页在客户端加载。

水合是安全的

布局副作用在浏览器里使用 useLayoutEffect，在服务端自动降级为 useEffect。服务端渲染时容器宽度未知，所以两端的首次渲染都是一个空容器，不会出现水合不一致。元素位置会在挂载后、测量到宽度时立刻计算。

服务端 HTML 里有什么

因为位置取决于测量到的宽度，即使传了 initialItems，服务端 HTML 里也不包含卡片。如果搜索引擎必须看到这些内容，请在布局旁边额外渲染一份可被抓取的列表（比如页面里的链接，或一个 <noscript> 块），或者把这个图库用在不需要被收录的内容上。

懒加载

布局只在浏览器里有意义，所以可以把它从首屏 bundle 里拆出去：

import dynamic from "next/dynamic";

const Gallery = dynamic(() => import("./Gallery"), { ssr: false });

只有在你不需要靠 initialItems 来避免加载闪烁时才这样用。
