分页与无限滚动

页是如何被请求的、下一页何时开始、出错时会怎样，以及如何重新开始。

loadData 约定

type LoadData = (
  page: number, // 从 1 开始，每成功请求一次加 1
  pageSize: number,
) => Promise<{ data: any[]; hasMore: boolean }>;

组件会保存所有已加载的元素。loadData 只需返回新的一页，库会把它追加进去。页码由组件内部维护，不需要你自己计数。

下一页何时开始

布局底部有一个 1px 的标记元素，一个 rootMargin 为 loadMoreThreshold 的 IntersectionObserver 监听它，所以当底部距离视口还有 loadMoreThreshold px 时就会开始请求下一页。每一页完成后，观察器会重新订阅并立刻检查当前状态：如果标记元素仍然在视口附近（快速滚动超过了内容），就马上开始下一页。

  • 用户滚动很快或接口较慢时，调大 loadMoreThreshold。
  • 确保 pageSize 能填满超过一屏。页太小的话，每次响应后标记元素仍然可见，请求会一个接一个连续发出。

同一时间只有一个请求

已有请求在进行时，不会再开始新的请求。这个判断是同步的，所以同一帧里连续触发多次也只会发出一个请求，响应也不会乱序。

请求失败时

loadData 被 reject 时，会用 console.error 记录，并停止自动翻页（hasMore 变为 false），避免标记元素仍可见时，坏掉的接口被无限循环调用。你可以按需选择恢复方式：

  • 用新的 key 重新挂载组件，从第 1 页重新开始。
  • 在你自己的 loadData 里捕获错误，完成自己的重试后，返回 { data: [], hasMore: true }，让翻页继续。

筛选条件变化时重新开始

组件挂载时加载第 1 页，之后不会自己重新加载。查询条件变化时，请重新挂载它：

<VirtualMasonry
  key={JSON.stringify(filters)}
  loadData={(page, size) => fetchImages({ ...filters, page, size })}
  renderItem={renderCard}
/>

配合 DynamicMasonryView

DynamicMasonryView 会自己调用第 1 页来获取布局类型，并把这份响应交给内部布局，所以第 1 页只请求一次。受控的 isMasonry 属性变化会重新挂载内部布局，并再次请求第 1 页。

去重

库不会去除重复数据。如果你的接口可能在两页里返回同一条记录（比如用户滚动期间有新数据插入），请在 loadData 里自行去重，并保证 key 稳定且唯一。
